## 1. Hanson QA Document Review Process Guide

### 📋 Complete Guide to Technical Document Review & Approval

#### QA Review Process Overview

🎯 Hanson's QA review process ensures all technical documents, calculations, drawings, and construction submittals meet quality standards. This process creates an audit trail showing independent verification of work products before client delivery.

**⚠️ KEY PRINCIPLE:** All technical work must be reviewed by someone OTHER than the originator. The Professional of Record (POR) manages the review process but may not serve as both originator AND reviewer for the same document.

### Types of Documents Requiring QA Review

#### 📊 Technical Calculations

**QUAL3090**

- Analysis, design calculations, quantities, cost estimates
- Form: QUAL3090.01/QUAL3092.01

#### 📐 Technical Drawings

**QUAL3091**

- Construction plans, layout drawings, plats of survey
- Form: QUAL3091.01 + Review/Revision blocks on drawings

#### 📄 Technical Documents

**QUAL3092**

- Reports, specifications, procedures, planning documents
- Form: QUAL3090.01/QUAL3092.01

#### 🏗️ Construction Submittals

**QUAL3093**

- Shop drawings, product data, samples
- Forms: QUAL3093.01, QUAL3093.02, QUAL3093.03

#### 🔧 Delegated Design

**QUAL3094**

- Contractor-provided designs/certifications
- Forms: QUAL3094.01, QUAL3094.02, QUAL3094.03

#### 📋 QA Documents

**QUAL3110**

- Project-specific QA plans and procedures
- Form: QUAL3110.01

### 📄 UNIVERSAL QA REVIEW WORKFLOW

1. **✏️ ORIGINATE** - Create document, Initiate form
2. **👤 ASSIGN** - POR assigns reviewer, Define scope
3. **🔍 REVIEW** - Independent check, Document comments
4. **🔧 RESOLVE** - Address comments, Update document
5. **✅ APPROVE** - POR approval, Sign form
6. **📁 FILE** - Store per QUAL3130, Project records

### Required QA Forms & Documentation

#### QUAL3090.01/QUAL3092.01 - Review of Technical Calculations/Documents

Used for both calculations (QUAL3090) and documents (QUAL3092). Dual-purpose form with same fields.

**Key Fields:**

- General info (project, document title)
- Type of calculation/document
- Scope of review checkboxes
- Originator signature & date
- Reviewer comments & signature
- POR approval signature

#### QUAL3091.01 - Manager Review of Drawings

Used for complete drawing sets. Individual drawings use review/revision blocks on the drawing itself.

**Key Fields:**

- Drawing set identification
- Contract compliance check
- Coordination verification
- PM/POR signature

#### QUAL3093.01 - Log of Submittals

Tracks all construction submittals. Categorizes as "actionable" (requiring review) or "informational" (acknowledgment only).

**Key Fields:**

- Submittal number & description
- Receipt date
- Category (actionable/informational)
- Review status
- Return date

#### QUAL3093.02 - Traditional Review of Submittals

Documents review when stamp cannot be applied directly to submittal (e.g., physical samples).

**Review Actions:**

- No Exceptions Taken
- Furnish as Corrected
- Revise and Resubmit
- Submit Specified Item
- Rejected - See Remarks
- For Information Only

#### QUAL3094.02 - Traditional Review of Delegated Design

For contractor-provided designs when Hanson prepared original contract documents.

**Review Actions:**

- No Comments
- See Comments (info only)
- Resubmit (Non-compliance)
- Resubmit (Incomplete)

#### QUAL3110.01 - Review, Approval and Posting Record

For client/project-specific QA documents. Tracks review from draft through final posting.

**Sections:**

- Section I-II: Document ID & reviewers
- Section III-IV: Review completion
- Section V: Officer approval
- Section VI: Posting verification

### Detailed Process by Document Type

#### 📊 Technical Calculations (QUAL3090)

**1. Originator prepares calculation package:**

- Statement of purpose
- Assumptions
- References for formulas/methods
- Results with supporting documentation
- Completes header on QUAL3090.01 form

**2. POR assigns reviewer and scope:**

- Math check for hand calculations
- Spot checks for spreadsheets
- Input/output review for software

**3. Reviewer performs review:**

- Marks corrections in RED
- Highlights reviewed items in YELLOW
- Defers items in GREEN for POR review
- Signs/dates form QUAL3090.01

**4. Resolution and approval:**

- Originator addresses comments
- If disagreement, POR resolves
- POR signs final approval

#### 📐 Technical Drawings (QUAL3091)

**Individual Drawing Process:**

- Originator signs "Drawn" block on drawing
- Designer signs "Designed" block
- Reviewer checks and signs "Reviewed" block
- All signatures/dates in review block on drawing itself

**Complete Drawing Set:**

- PM/POR reviews entire set for coordination
- Completes QUAL3091.01 for the set
- Verifies contract compliance

**Major Revisions:**

- Use revision block (not review block)
- Original signatures remain unchanged
- Add sequential revision number/letter

#### 📄 Technical Documents (QUAL3092)

**Process Flow:**

- Originator completes draft document
- Initiates QUAL3092.01 (same form as calculations)
- POR assigns reviewers (can be multiple)
- Reviewers use Track Changes or mark up PDF
- Originator dispositions comments
- Editorial review for grammar/format
- POR performs final management review
- Document authenticated if required

💡 **TIP:** Use Track Changes in Word or comment tools in PDF for efficiency. Form QUAL3092.01 can be completed electronically but signatures must not be editable in final version.

#### 🏗️ Construction Submittals (QUAL3093)

**Pre-Review Checks:**

- Verify contractor has reviewed/approved (required stamp)
- Confirm submittal relates to Hanson's design
- Categorize as actionable or informational
- Log in QUAL3093.01

**Review Process:**

- Check conformance with design intent only
- Apply review stamp or use QUAL3093.02
- Do NOT review means/methods
- Return with transmittal

⚠️ **CRITICAL:** If contractor hasn't reviewed submittal first, RETURN WITHOUT REVIEW unless POR provides written waiver.

### Summary of Review Requirements

|Document Type|Required Form(s)|Review Documentation|Special Requirements|
|---|---|---|---|
|**Calculations**|QUAL3090.01|On calculation sheets + form|Spot checks for spreadsheets required|
|**Drawings**|QUAL3091.01 + drawing blocks|On drawing itself|Review block or revision block on each sheet|
|**Documents**|QUAL3092.01|Track changes or markups|Editorial review after technical review|
|**Shop Drawings**|QUAL3093.01, .02 or .03|Stamp or form|Contractor must review first|
|**Delegated Design**|QUAL3094.01, .02 or .03|Form (no stamp for nontraditional)|Must have CDOR authentication|
|**QA Documents**|QUAL3110.01|On form sections I-VI|Officer approval required|

### ⚡ Quick Reference Notes

**📄 Independence Rule:** Reviewer must be independent of originator. POR cannot be both.

**📁 Records Management:** All completed forms go to project files per QUAL3130.

**🖊️ Digital Signatures:** DocuSign, Adobe, or Bluebeam only. No typed signatures.

**⏱️ Review Timing:** Review must occur before client submittal or use.

💡 **BEST PRACTICE:** Start the QA form when you start the document. Don't wait until the end. This ensures proper documentation throughout the process and prevents missing signatures or information.

### 📊 Complete QA Data Collection Overview

- **6** Primary Forms (QUAL3090.01/3092.01, QUAL3091.01, QUAL3093.01/.02/.03, QUAL3094.01/.02/.03, QUAL3110.01)
- **50+** Data Fields (Project info, document details, review scopes, comments, dispositions, approvals)
- **7** Role Types (Originator, Reviewer, POR, PM, Coordinator, Editor, Hanson Officer)
- **15+** Signatures Required (Multiple signatures per form with corresponding dates for complete audit trail)

💡 **EFFICIENCY INSIGHT:** Each document review requires 4-7 different people to input data across multiple forms, with 15+ signatures and dates. Digital review tools (SharePoint, Adobe, Bluebeam) could capture this same data automatically through the review workflow, reducing manual data entry by approximately 75% while maintaining full compliance.

- **I - Informed**: Kept updated

- **PM** - Project Manager
- **PP** - Project Principal
- **POR** - Professional of Record
- **OR** - Originator
- **RV** - Reviewer

- **ED** - Editor
- **QA-S** - QA Specialist
- **CQAO** - Corporate QA Officer

### Additional QA Procedures - Key Responsibilities

#### 📐 Review of Technical Drawings (QUAL3091)

- **PM/POR**: Accountable & Responsible for reviewing drawing sets/series
- **PM/POR**: Responsible for completing drawing review form
- **PM/POR**: Responsible for tracking revisions

#### 📁 Control of Project Records (QUAL3130)

- **PM**: Accountable for ensuring record compliance
- **PM**: Accountable for assigning record storage responsibilities
- **IT**: Responsible for maintaining servers/backups
- **Originator/Reviewer**: Responsible for applying naming conventions
- **PM**: Responsible for duplicating client-hosted DMS records internally

#### ✅ Corporate QA Program Roles (QUAL4000)

- **PM**: Accountable & Responsible for implementing CQAP
- **CQAO**: Responsible for conducting audits/surveillance
- **CQAO**: Accountable & Responsible for assigning QA training
- **PM/CQAO**: Accountable for halting services for QA issues

### 📊 RACI Analysis Summary

**PM** - Most Accountable Role - Primary accountability for QA compliance

**POR** - Technical Authority - Accountable for technical content

**11** - Total Roles - Involved in QA processes

**PP** - Escalation Point - Resolves conflicts when POR involved

🔍 **Key Insight:** The PM carries the highest accountability burden across all QA processes, being accountable for document decisions, comment resolution, record compliance, and CQAP implementation. The POR holds technical accountability, while the PP serves as the escalation point when conflicts involve the POR. This creates clear escalation paths but also concentrates decision-making responsibility heavily on the PM role.

⚠️ **Process Observation:** Multiple people are "Responsible" for the same tasks (e.g., OR and RV both responsible for resolution facilitation), which can create confusion about who actually does the work. Digital tools could clarify this by automatically routing tasks to the correct person based on workflow stage.

## 4. Document Review Guide - Microsoft Office Native Process

### 📊 Native Document Review in Office

**Track Changes, Comments, and Co-authoring Without PDFs**

### MICROSOFT 365 Application Options

#### 📝 Word

- Reports, Specs, Procedures

#### 📊 Excel

- Calculations, Estimates, Data

#### 💬 Teams/SharePoint

- Real-time Collaboration

### 📄 MODERN OFFICE REVIEW WORKFLOW

1. **📄 CREATE** - Native Office file
2. **☁️ UPLOAD** - SharePoint/OneDrive
3. **👥 SHARE** - Send review link
4. **✏️ CO-AUTHOR** - Real-time editing
5. **💬 REVIEW** - Comments & track changes
6. **✅ FINALIZE** - Accept/reject changes

### WORD: Track Changes for Reports & Specifications

#### 🎨 DOCUMENT ORIGINATOR

1. **Prepare document**
    - Review tab → Track Changes ON
    - Set user name (File → Options)
    - Lock tracking if needed (with password)
2. **Save to SharePoint**
    - File → Save As → SharePoint location
    - Or upload to Teams channel
3. **Share for review**
    - Click Share button
    - Set permissions (edit/comment/view)
    - Add message for reviewers
4. **Monitor changes**
    - See who's currently editing (presence)
    - View changes in real-time
    - Respond to comments
5. **Finalize document**
    - Review → Accept/Reject changes
    - Delete resolved comments
    - Compare versions if needed

💡 **PRO TIP:** Use "Simple Markup" view during review to see clean document with change indicators in margin. Switch to "All Markup" to see details.

#### ✏️ REVIEWERS

1. **Open shared link**
    - Opens in Word desktop or browser
    - Your name appears on edits
2. **Review tools available:**
    - Track Changes for edits
    - Comments for questions/suggestions
    - @mentions to notify specific people
    - Reply to existing comments
    - Suggest formatting changes
3. **See others working**
    - Colored flags show who's where
    - Changes appear as they type
    - No save conflicts
4. **Review complete**
    - All changes auto-saved
    - Can leave final comment
    - Close and changes persist

⚠️ **IMPORTANT:** Track Changes must be ON before editing. Check the Review tab - if it's OFF, your changes won't be tracked for QA!

### EXCEL: Comments & Change Tracking for Calculations

#### 💬 Comments & Notes

Two systems: Comments (threaded conversations with replies) and Notes (simple annotations). Comments are perfect for review discussions. Right-click any cell → New Comment.

#### 🔐 Protection with Exceptions

Protect sheets but allow specific ranges for input. Review tab → Protect Sheet → Select what reviewers can change. Perfect for calculation templates.

#### 🔍 Track Changes (Legacy)

Review tab → Track Changes → Highlight Changes. Shows who changed what cell and when. Note: Being phased out in favor of version history.

#### 📄 Version History

File → Info → Version History. See all previous versions, who made changes, and restore if needed. More reliable than Track Changes.

#### 👁️ Show Changes

New feature in 365: See changes highlighted in real-time as others edit. Green = additions, Red = deletions. Temporary visual during co-authoring.

#### ✅ Data Validation Comments

Add input messages and error alerts to cells. Data tab → Data Validation → Input Message. Guides reviewers on acceptable values.

💡 **EXCEL BEST PRACTICE:** Create a "Review Log" worksheet in your file. Include columns for: Reviewer, Date, Cell Reference, Issue, Response, Status. This becomes your QA documentation.

### Office Native vs. PDF-Based Review

|Aspect|Office Native Review|PDF Review (Adobe/Bluebeam)|
|---|---|---|
|**File Format**|Stay in Word/Excel - no conversion|Must export to PDF first|
|**Real-time Collaboration**|✔ Multiple users simultaneously|~ Sequential or managed sessions|
|**Change Tracking**|✔ Automatic with user names|✗ Comments only|
|**Version Control**|✔ Automatic in SharePoint|~ Manual versioning|
|**Formula Checking**|✔ Can audit Excel formulas|✗ Formulas not visible|
|**CAD Drawings**|✗ Not suitable|✔ Designed for drawings|
|**Final Deliverable**|Export to PDF after review|Already in PDF format|
|**QA Documentation**|✔ Changes tracked automatically|~ Export comment summary|

### Meeting QUAL3130 Requirements with Office

#### 📍 Automatic Audit Trail

Every change shows: who, what, when. Reviewing Pane in Word shows complete history. Excel comments are timestamped. Meets traceability requirements.

#### 🔐 Authentication

Users authenticated through Microsoft 365 accounts. Changes tied to corporate identity. Can add digital signatures through Insert → Signature Line.

#### 📁 Folder Compliance

Files stay in your Admin folders during review. No need to move for review process. Final PDF goes to 17-Deliverables after changes accepted.

#### 📊 Review Summary

Word: Print markup summary or save as PDF with comments. Excel: Export comments or create review log. This replaces separate QA forms.

### ⚡ Quick Reference Guide

#### 🚀 Starting Co-authoring

**Word/Excel:**

1. Save to SharePoint/OneDrive
2. Click Share button (top right)
3. Enter email addresses
4. Choose "Can edit"
5. Add your message
6. Send Everyone can now edit simultaneously!

#### ⌨️ Essential Shortcuts

**Word:**

- `Ctrl+Shift+E` - Track Changes
- `Ctrl+Alt+M` - New Comment
- `F5` - Go to specific change

**Excel:**

- `Shift+F2` - Add Comment
- `Ctrl+Shift+L` - Filter
- `Alt+R+G` - Protect Sheet

#### 💥 @Mentions

Type @ in a comment followed by someone's name. They get an email notification with a link directly to that comment. Great for getting specific input. Works in: Word, Excel, PowerPoint

#### 📊 Version Comparison

**Word:** Review → Compare → Two versions **Excel:** File → Info → Version History, Click any version to open **SharePoint:** Right-click file → Version History

#### 🔐 Locking Tracking

**Force Track Changes:** Word: Review → Track Changes → Lock Tracking (set password) Now NO ONE can turn off tracking without the password. Ensures QA compliance.

#### ✅ Creating Final Version

**Word:**

1. Accept all changes
2. Delete all comments
3. File → Info → Check for Issues
4. Save as PDF for deliverable **Keep the marked-up version for QA records!**

### Why Office Native Review Works for Our Team

🚀 **No Training Needed** - Everyone knows Word & Excel already

♻️ **Stay in Native Format** - No PDF conversion until final

👥 **True Collaboration** - Multiple people editing simultaneously

📍 **Automatic QA Trail** - Every change tracked without forms

## 5. CAD Drawing Review in SharePoint

### 📐 Simplified Process for DWG, DXF, and Other CAD Files

### 📄 THE CAD REVIEW WORKFLOW AT A GLANCE

1. **🎨 DESIGN** - Create/update in AutoCAD, Revit, SolidWorks, etc.
2. **📄 EXPORT** - Plot to PDF (full size, color)
3. **☁️ UPLOAD** - Both files to SharePoint folders
4. **✏️ REVIEW** - Markup PDF, check QA items
5. **✅ APPROVE** - Digital approval & transmittal

### How to Organize Your CAD Files in SharePoint

```
📁 Project XYZ-2025
    📁 01_Working_Drawings
        📊 A-101_FloorPlan_Rev2.dwg
        📄 A-101_FloorPlan_Rev2_REVIEW.pdf
    📁 02_Approved_Drawings
        📊 A-101_FloorPlan_Rev1.dwg
        📄 A-101_FloorPlan_Rev1_APPROVED.pdf
    📁 03_Superseded
        📊 A-101_FloorPlan_Rev0.dwg
```

⚠️ **CRITICAL RULE:** Always upload BOTH the native CAD file (.dwg) AND the PDF export. The CAD file is for record-keeping, the PDF is for review and approval.

### Step-by-Step Instructions

#### 🎨 FOR DESIGNERS/DRAFTERS

1. **Finish your drawing** in CAD software
2. **Plot to PDF:**
    - Use "DWG to PDF.pc3" plotter
    - Select "Full Size" (not "Fit to Page")
    - Include layers & lineweights
3. **Name your files:** `[Drawing#]_[Title]_Rev[#]`
4. **Upload to SharePoint:**
    - DWG → Working_Drawings folder
    - PDF → Same folder, add "_REVIEW"
5. **Add metadata** when prompted:
    - Drawing Number
    - Revision
    - Scale
    - Select Reviewer from dropdown
6. **Auto-notification** sent to reviewer!

💡 **PRO TIP:** Create a PDF preset in AutoCAD for consistent exports. Save as "SharePoint Review" for one-click plotting.

#### ✏️ FOR REVIEWERS/APPROVERS

1. **Click link in email** notification
2. **PDF opens** in browser (or download for detailed review)
3. **Review using PDF tools:**
    - Add comments/clouds
    - Measure dimensions (if needed)
    - Check against standards
4. **Complete QA checklist** (appears automatically):
    - Title block information correct
    - Scale and dimensions verified
    - Drawing standards compliance
    - Cross-references checked
    - Revision clouds present (if applicable)
5. **Click "Approve"** or **"Needs Revision"**
6. **System records** your review automatically

⚠️ **REMEMBER:** You're reviewing the PDF, not the CAD file. If you need to check something in CAD, download the DWG separately.

### ⚡ Quick Reference Cards

#### 🔍 Finding Drawings

**By Drawing Number:** Use search box, type drawing number **By Status:** Filter view to "Pending Review" or "Approved" **By Date:** Sort by "Modified" column

#### 📁 File Size Limits

**Maximum file size:** 250MB **If file is too large:**

- Purge unused blocks in CAD
- Use ZIP for multiple files
- Contact IT for large models **Typical sizes:** DWG: 5-50MB | PDF: 1-10MB

#### 📄 Revision Process

**After reviewer comments:**

1. Download marked-up PDF
2. Update CAD drawing
